Overview

QwenAtHome

Measured local Qwen inference experiments on one RTX 5070 Ti 16 GB: llama.cpp, Strata, MTP, DFlash2, prompt lookup, quantization, and context limits.

Open the standalone HTML documentation by downloading the repository and opening that file locally. GitHub displays HTML source; GitHub Pages is not configured by this change. The HTML needs no server, JavaScript, external assets, or network access to read.

What held up

MTP helped these short coding fixtures. Context lookup helped most when output copied input. Prefix caching made repeated long-context requests dramatically quicker. A loaded model and a configured context limit did not establish stable long-context performance. Fresh-code failures occurred despite good generation speeds.

The last configured profile in this record was Huihui at 32K with Q8 KV and MTP. This repository does not monitor or control a running server. It contains no model weights, inference binaries, credentials, or personal chat exports.

Sequence of experiments

  1. Earlier Qwen3.6-35B-A3B / small-VRAM exploration was discussed. No comparable retained results support a benchmark table for it; do not treat the early 8 GB discussion as the final machine specification.
  2. Installed official llama.cpp b12110 (cd959bae9), Windows CUDA 13.4, and Qwen3.8-27B UD-IQ4_XS.
  3. Compared ordinary decoding, MTP depths 1/3/5, full GPU offload, and Q4 main KV. Tested DFlash2 and MTP plus ngram lookup.
  4. Validated three focused coding tasks and beginning/middle/end retrieval near 8K, 16K, and 32K. Saved separate general and editing profiles.
  5. Downloaded/prepared Flash IQ2_XS for Strata terminal 0.2.7 / engine 0.1.52. Stopped the other engine before loading it. Closing a large competing application freed RAM before measurement; concurrent application load materially affected fit.
  6. Increased Strata's VRAM reserve to 1,500 MiB, then ran three coding rounds, everyday fixtures, and context retrieval. The initial low-headroom trial is retained separately and excluded from final medians.
  7. Attempted Flash at 64K. It reached ready but warned of 1.3 GiB Windows commit headroom versus 2.0 GiB planned allocations plus reserve. No 64K retrieval was submitted. Restored 32K. No page-file change was made.
  8. Returned to dense 27B, then downloaded Q3_K_XL and allocated 84,992 context. Near-84K retrieval passed but took 237.38 seconds cold and 1.44 seconds resumed; sampled VRAM headroom fell to 115 MiB.
  9. Disabled MTP at 85K: short generation was about 48 tok/s. Tried main microbatch 64 / draft microbatch 16: faster short edits (114–119 tok/s), but long prefill slowed above 60K and hit the 300-second HTTP timeout. Server released at 65,024 processed tokens. Reverted to microbatch 128; final chat measured 67.8 off / 65.1 on. Exact paging cause was not conclusively isolated.
  10. Downloaded Huihui GSQ-RCO IQ3_S-MTP, verified SHA256, and ran 32K with Q8 main and draft KV. Chat completed at 67.4 tok/s; two edits passed; the fresh generator failed; near-32K retrieval passed with 860 MiB minimum sampled free VRAM.

Methodology

Methodology and reproduction

What each number means

  • Decode tok/s: the engine's timings.predicted_per_second, excluding prompt processing.
  • Prompt processing: prompt_ms / prompt_per_second, covering newly read tokens as reported by that engine.
  • Wall time: HTTP request elapsed time when explicitly captured; it includes input processing and generation.
  • Cached tokens: reported prompt reuse, not newly read input. Prefix reuse reduces repeated prefill; lookup proposes output tokens copied from context. They are distinct optimizations.
  • Context allocation: the configured total window, not proof that a benchmark filled it. Prompt plus generation must fit.
  • Thinking: generated reasoning can consume output tokens and time. Thinking-on results cannot be equated with thinking-off answers of different lengths.

Coding fixtures

Three unique synthetic Python tasks: TTL expiry and zero TTL; CSV delimiter/escaping propagation without input mutation; lazy stable merging of sorted event iterables. Each has a focused executable check. Generated modules were AST-screened and run in separate Python processes with an eight-second timeout. That filter is not a security sandbox; use a disposable VM/container if executing untrusted model output.

The retained harness uses the Python standard library. Examples, with an already-running local llama.cpp server:

$env:BENCH_URL = 'http://127.0.0.1:8081'
$env:MODEL_ALIAS = 'Huihui-Qwen3.8-27B'
$env:BENCH_OUTPUT_DIR = 'benchmark-output'
python benchmarks/focused_checks.py my-run
$env:CONTEXT_RESULTS = 'my-context-results.json'
python benchmarks/focused_checks.py context 32000

This harness calls llama.cpp /tokenize and /detokenize; it is not a drop-in Strata context harness. Strata's context inputs were built with its pack's local tokenizer because those HTTP endpoints returned 404. The public harness writes results and screened modules under BENCH_OUTPUT_DIR; use a unique run name to avoid overwriting them. It does not launch or stop servers.

Coding requests used temperature 0, seed 42, thinking disabled, and up to 1,600 generated tokens. A failure can be a runtime error or output-cap truncation, not just slow inference. Raw JSON includes completion status, outputs, and validation errors.

Context fixtures

Archive-like filler contained three reference values near the start, middle, and end. A follow-up requested the same values with reordered keys. JSON values were checked after extracting an object, so replies with Markdown fences could pass semantic retrieval while violating strict JSON formatting. Results say retrieval passed, not that strict structured-output compliance passed.

Near-32K cold input was 31,916 tokens; near-84K cold input was 83,916. Follow-ups reused most previous tokens. GPU memory was sampled about every 0.75 seconds; short peaks may be missed. Most context checks were one cold request and one follow-up per size.

Statistical limits

IQ4_XS coding checks were one generation per task per profile. Flash's final short-task values are medians of three sequential rounds on a single engine; expert caches warm across rounds, and unique input prefixes prevented full prompt reuse. Q3 and Huihui were small single-request comparisons. Outputs, precision, sampling, reasoning, and context allocation differ, so no universal model ranking or guaranteed speedup follows.

No fresh GPU inference was run to prepare these public documents. Existing retained measurements were summarized and sanitized. The public code keeps the same three focused checks, rather than expanding the evaluation suite.

Setup

Running the recorded profiles

Requirements

The recorded dense-model runtime was official llama.cpp b12110 (cd959bae9), Windows CUDA 13.4. Download the corresponding runtime and selected GGUF yourself; neither binaries nor weights are in this repository. Later builds may change CLI names, output, and performance. Verify downloaded checksums against the model publisher.

Set LLAMA_SERVER to the executable's full path and MODEL_DIR to the directory holding the GGUF files. For example, in PowerShell, using your actual locations:

$env:LLAMA_SERVER = Join-Path $PWD 'runtime/llama-server.exe'
$env:MODEL_DIR = Join-Path $PWD 'models'
& ./profiles/Start-Huihui-Qwen38.cmd

Keep the server terminal open. Open http://127.0.0.1:8081 after it loads. Stop the existing server before launching another; every profile uses the same port. The scripts check required environment variables but do not download models, kill processes, alter clocks, or change the page file.

API and Hermes

Use an OpenAI-compatible Chat Completions endpoint at http://127.0.0.1:8081/v1. The Huihui model alias is Huihui-Qwen3.8-27B; other launchers use Qwen3.8-27B. The historical local server did not require a key and bound only to localhost. Do not publish actual credentials in documentation. Match a client/Hermes context override to the serving profile, rather than the larger native context advertised by model metadata. Refresh the UI and choose the matching alias after switching models.

Hermes supports automatic compaction, but it was researched rather than verified through a complete local agent workflow. See official context documentation.

Strata Flash baseline settings

Recorded terminal 0.2.7 / engine 0.1.52; Flash Next IQ2_XS; 32K; vision off; MTP on; KV int8; --expert-cache auto --prefill auto --spec 4 --spec-min-p 0.5 --vram-reserve-mib 1500. Default route-tail-skip 7 remained enabled, so this was not a claim of bit-identical full-model arithmetic.

Strata setup had prepared native model/pack/MTP directories. Their machine-specific paths and configuration files are not published. An install was staged using strata install -- ... --no-start; launch then used a saved Flash preset. Use the matching version's help for data-directory and preset handling. The IQ2_XS shards together occupy about 68 GB decimal on disk, distinct from runtime resident memory.

At 64K, a Windows commit warning prevented further testing. Available physical RAM alone does not establish commit headroom; no page-file modification was performed. --kv-grow is a separate Strata memory mode; it was not applied in these local Flash measurements.

Strata KV growth and upgrade

--kv-grow allocates physical KV as needed, letting expert cache use the rest at short contexts. It needs a compatible single-GPU mode, expert profile, all experts in RAM, and full GPU KV rather than KV streaming. It is not a generic llama.cpp flag. Long-context growth can trade away expert cache and change performance; a larger configured window alone is not validation.

The local baseline was engine 0.1.52. Version 0.2.10 and engine 0.1.56 were researched, but not installed or benchmarked. A 5080 Windows slowdown report motivated retaining a baseline; it does not prove every newer version is slower. A KV-grow / prefill interaction report illustrates why a configured large context still needs testing.

HyperQwen: correction to a circulated summary

The original creator's project is syv-ai/HyperQwen, formerly qwen38-27b-rtx3090. It patches vLLM, not llama.cpp. TeksEdge amplified the result; the original developer post described ~133 tok/s chat, ~382 while reproducing context, 16-token verification with about 15 accepted in a favorable workload, and important long-context tradeoffs/corrections.

Lookup and prefix caching are distinct: lookup proposes output tokens from context; prefix caching avoids reprocessing input. The recipe also changes quantization and kernels; it is not just a flag that makes an existing GGUF 4.6 times faster. The published 24GB preparation is not a demonstrated fit on this 16GB setup. No HyperQwen download, conversion, installation, or benchmark was performed locally.

Privacy

Privacy and publication scope

Only an explicit allowlist of synthetic benchmark results, reports, portable profiles, and the focused benchmark harness is published.

Excluded: user names, home/workspace paths, machine names, hardware serials/UUIDs, personal emails, API keys, auth files, application sessions, private chats, attachments/screenshots, full process lists, complete system logs, model weights, runtime binaries, and unrelated project files.

Windows absolute paths in retained JSON/errors are replaced with placeholders. Some synthetic fixture basenames and public model/repository identifiers remain because they identify the experiment. Localhost endpoint examples are generic. Commit attribution uses a generic documentation identity rather than an account's local Git name/email.

Raw data contains synthetic prompts, generated code, and a basic security-review response. These are evidence rather than executable recommendations. File hashes refer to public model artifacts. Hardware is described only at the model/specification level needed to interpret performance.

The original local files were not modified by sanitization. The repository's documentation commit is the intended publication boundary; no unrelated workspace files or account configuration are staged.

The full initial read near 84K took about four minutes; the cached follow-up took 1.44 seconds. The larger window fits narrowly and needs workload-specific validation before relying on long autonomous sessions. The focused fresh-code failure remains a material limitation.
